Philosophie

S’inspirer des déplacements dans vim pour optimiser les déplacements dans Reaper, et idéalement se passer de souris.

J’essaye au maximum de coller aux raccourcis de Vim mais je dois prendre des libertés. En effet, dans vim on se déplace dans un projet verticalement. Les déplacements horizontaux, se font dans le contexte de la ligne de code, ou de la phrase.

Dans Reaper, ce qui correspond au déroulement chronologique d’un “projet” de vim, ça serait plutôt les déplacement horizontaux. Il y a un début home - gg et une fin end - G. Seulement, même si ça correspond moins au déroulement chronologique, on a aussi un déplacement vertical très présent dans Reaper, c’est celui des pistes qui sont agencées verticalement les unes sur les autres.

Naturellement on a envie de faire l’analogie des déplacements verticaux entre vim et reaper. Dans vim on utilise la flèche vers le bas (j) pour aller de l’avant dans le déroulement du code, aller vers la prochaine fonction, etc … Dans reaper, on a envie d’utiliser la flèche du bas pour aller dans la piste d’en dessous, pas pour aller au prochain couplet ou à la prochaine mesure.

Je prends donc les déplacements verticaux de vim que je transforme en déplacement verticaux ET horizontaux dans Reaper.

Les déplacements horizontaux dans vim

Il me semble que la ligne de code dans vim correspond à l’item dans reaper ou alors l’ensemble d' Une petite section d’arrangement.

Dans Reaper, qu’est-ce qui correspondrait à la ligne ? C’est quoi une ligne dans vim ? C’est soit une phrase ou un paragraphe dans un contexte littéraire, soit une ligne de code, c’est une déclaration, une action, une instruction.

Dans un contexte muscial, j’imagine que ça serait une phrase mélodique. Par exemple dans un couplet, il y a une phrase mélodique répétée deux fois puis une autre, et une variante de la première, etc …

Donc :

  • un couplet, matérialisé par une région dans Reaper
  • une phrase (non matérialisée)
  • des mots Là c’est un peu difficile de faire le rapprochement avec vim, je propose néanmoins:

Les mots, ce sont les items. Ils n’existent pas en soi Les items n’existent pas en soi, pas par eux-mêmes. Si on crée des items, c’est qu’on a un besoin d’édition, donc un item peut correspondre à un couplet, une phrase, ou une seule note …

Je propose de dire arbitrairement qu’un item correspondrait à une phrase, une ligne de code.

sentence: groupe of items collés ( ) voir xraymscripts mots: items b w lettres: décomposition de la grille l h

La lettre devrait être idéalement la note, malheureusement je n’ai pas de moyen très efficace pour l’identifier.

Schéma

Raccourcis verticaux

Selection

  • j – next track
  • k – previous track
  • i – first track visible
  • o – track in the middle of the screen
  • p – last track visible /!\ select bottom track in arrange view → Paste

Scroll

Reposition the edit window vertically (the part of the project that you see) while keeping the same track selected:

  • zz – position the selected track in the middle of the edit window
  • zt – position the selected track at the top of the edit window
  • zb – position the selected track at the bottom of the edit window

this does not keep the same track selected :

  • C-D – scroll windows downward half a screen
  • C-U – scroll windows upward half a screen

go to older position in jump list go to newer position in jump list Bon, elles ne semblent pas évidentes ces deux-là. À la limite je pourrais utiliser l’alternate buffer, peut-être avec ça: https://forums.cockos.com/showthread.php?t=252442
