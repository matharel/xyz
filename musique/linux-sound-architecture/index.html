Linux Audio Explained

Drivers

In the kernel we need driver to interact with the hardware soundcard. In the early day of Linux it was commonly done with Open Sound Systme - OSS.

ALSA - Advanced Linux Sound Architecture - is its successor. It supports everything :

  • usb soundcard
  • pca soundcard
  • onboard audio
  • …

Also provides the drivers necessary to read/write from a soundcard.

And that’s all, it’s just a mean to interact with the soundcard. Many applications support working with alsa directly (reaper, VLC, …) without a soundserver.

In practice, if a program use ASA it will take control of the entire soundcard

ALSA is robust but to deal with multiplex sound we need an abastracted layer above ALSA.

Sound Server

These days it is pulseaudio and more recently pipewire. The servers are going to interact with the soundcard and the programs are the client. Each of these clients output their sound to the server that will combine those sounds and output it to the soundcard.

The benefices are:

  • no matter how much output my soundcard have, I can have how many programs I want.
  • the sound server can redistribute the sound coming from the microphone to different applications
  • if applications does not use the same sample rate, the server do the resampling
  • can use several soundcards at the same time

Pulseaudio is doing all that. A concurrent is Jack but in the proaudio space.

Jack was designed as a virtual patch panel and is way more flexible than pulseaudio albeit slighter harder to use.

Pulse Audio drawbacks:

  • it’s hard to have a program that use 2 devices at once, or connect any input to any ouput.
  • latency: between 40 to 80 milliseconds

JACK - Jack Audio Connection Kit. Jack is very similar to pulseaudio, it’s a sound server so all programs send their sound to jack and jack do the interaction with ALSA (which usualy interacts with the soundcard).

JACK: Jack is a simple way to connect the output of any program to the input of any other program.

Benefits in comparaison of pulseaudio

  • it’s a patch panel, I can do any combinaison routing, I want between applications and physical inputs & output
  • has very little latency
  • supports MIDI

But it’s not everywhere because:

  • PulseAudio is easier to work with
  • simpler
  • works out of the box
  • most people (or applications) don’t need midi nor low latency

PulseAudio and Jack are not compatible. Pipewire will be the ultimate replacement for both Jack2 and pulseaudio.

It takes the ease of use and simplicity and the advance features set of jack and combine them.

Any program that used to work with pulseaudio or jack will work with pipewire.

Pipewire guide

github

Key features of PipeWire:

  • capture and playback of audio and video with minimal latency
  • Real-time multimedia processing
  • Multiprocess architecture to let applications share multimedia content.
  • Seamless support for pulseaudio, JACK, ALSA and Gstreamer applications.

You should use Pipewire … NOW!!!

Pipewire can make application that use pulseaudio communicate with applications that use jack. You need to install the following packages:

pacman -S pipewire-jack pipewire-alsa pipewire-pulse qjackctl
  • pipewire-jack is a replacement for jack
  • pipewire-pulse is the replacement for pulse
  • pipewire-alsa in order to inteface with the alsa system that is already built-in linux.

qjackctl is juste a graphical user interface to manage all that.

rtcqs (formely known as realtimeconfigquickscan)

Il faut d’abord installer le repo proaudio

github repo

Add the repo to your /etc/pacman.conf :

[proaudio]
Server = https://arch.osamc.de/$repo/$arch

Download, import and sign the current signing key:

curl https://arch.osamc.de/proaudio/osamc.gpg | sudo pacman-key --add -
sudo pacman-key --lsign-key 762AE5DB2B38786364BD81C4B9141BCC62D38EE5
sudo pacman -Sy

You can now install packages from the repo using pacman -Syu <package>

sudo pacman -S rtcqs

Install realtime-privileges

sudo pacman -S realtime-privileges

Add user to “realtime” group and “audio” group:

sudo usermod -a -G realtime,audio $USER

reboot

Set CPU Frequency Scaling

Install this set of userspace utilities designed to assist with CPU frequency scaling:

pacman -S cpupower

Run as root:

cpupower frequency-set -g performance

Kernel tweaks

sudo nvim /etc/default/grub

change GRUB_CMDLINE_LINUX="" to:

GRUB_CMDLINE_LINUX="threadirqs cpufreq.default_governor=performance"

et ici ils disaient:

GRUB_CMDLINE_LINUX_DEFAULT="quiet splash threadirqs"

Update Grub and reboot:

Definitions

Xrun:
it’s a buffer under-or-overrun, X stands for under or over. It’s a sign that your system did not process some buffers in time, so some data is missed. It is particularly true when you run at very low buffer size where the sound card should process incoming buffers very fast (overrun). Some chips cannot cope with small buffer sizes, so you have to increase the buffer length to ease the work done by the sound chip.
