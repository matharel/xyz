The D of systemd

D-Bus (Desktop Bus) is a high-level message-passing mechanism for Inter-Process Communication (IPC).

The D-Bus daemon runs two busses, virtual channels where messages fly back and forth :

  • The System Bus: system-wide services (NetworkManager, systemd)
  • The Session Bus: a private bus for each logged-in user, handling things like desktop notifications and applications communication.

When a program connects to a bus, it gets a bus name (e.g., org.freedesktop.NetworkManager). This how we can talk to a given service, it’s a DNS for D-Bus.

The systemctl commands is a user-friendly wrapper for making D-Bus calls. Some’s say it’s just a collection of tools.

When we type systemctl start my-app.service, we’re sending a D-Bus message to the systemd process (PID 1), which is a D-Bus service. We could do it by the busctl tool, but it’s a lot of harder work !

Cgroups

Control groups provide the isolation of hardware resources (CPU, Memroy, I/O, etc.) between processes, and keep processes isolated from each other.

systemd uses cgroups extensively to provide a level of security and isolation to all processes on the machine. Every single process runs in one cgroup.

  • .slice: a group of cgroups, like a folder organizing other cgroups. The whole system starts in the root slice (-.slice), with user porcesses in user.slice and system services in system.slice.
  • .service: A cgroup for a service unit, like gammastep.service.
  • .scope: A cgroup for grouping “foreign” processes that systemd didn’t start itself but still want to monitor (the user login session - greetd - for example).

Systemd Units

In systemd everything is a “unit”.

A unit is a declarative configuration files that tell systemd what you want done, not how to do it.

11 Differents type of units

But the ones we interact with :

  • .service: starts and controls a process (daemon or any process)
  • .socket : when traffic arrives on this socket, systemd will active the corresponding .service unit. It allows service to be started on-demand.
  • .target: a way to group other units and create synchronization points. Hooks for dependencies (WantedBy, RequiredBy).
  • .timer: trigger units on a calendar schedule
  • .slice and .scope: in relation to cgroups.
    • .slice: unit used to group other units in the cgroup tree
    • .scope: unit used to manage “foreign” process that systemd wants to track

Unit files

The [unit] Section

Contains information about the unit and its relationship with other units.

  • Description=
  • Wants=: “weak” dependency, it a unit list here fails, systemd starts the unit anyway.
  • Requires=: “strong” dependency. (better to use wants)
  • Conflicts=: The opposite of Requires.
  • After= and Before=: startup order.

The [Install] Section: Enabling and disabling

Tells systemctl how to hook the unit into the boot process.

The [Service] Section

This section is specific to .service units and defines how to run the process.

Execution Environmnet

  • WorkingDirectory
  • User= and Group=
  • Environment=
  • EnvironmentFile=

Overriding Unit Files

systemctl edit my-app.service

We only specify the sections and directives we want to add or change:

[Service]
Restart=always

After making changes to unit files, we must run systemctl daemon-reload.

Unit Management Commands

  • systemctl start|stop|restart
  • systemctl enable|disable: Enables unit to start at boot by creating the symlink defined in the [Install] section.
  • systemctl enable --now: enable and start.
  • systemctl daemon-reload: Reloads all unit configuration files from disk.

The Journal

The systemd-journald daemon collects log messages from a variety of sources:

  • Kernel messages
  • Messages from all services managed by systemd

journalctl dump the entire journal, filter it:

  • Follow logs live: journalctl -f
  • Show logs for a specific units: journalctl -u pipewire.service
  • filter by priority: journalctl -p err
  • kernel messages: journalctl -k

Conclusion

From D-Bus IPC and cgroup process management to the declarative unit system and the structured journal, systemd provides a comprehensive, integrated suite of tools for managing a modern Linux system.
