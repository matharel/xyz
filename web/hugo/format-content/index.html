Les attributs en Markdown

On peut ajouter des attributs sur les images et sur les éléments de block suivants:

  • blockquotes
  • fenced code blocks
  • headings
  • horizontal rules
  • lists
  • paragraphs
  • tables

Pour class et id, on peut utiliser la notation concise :

Voici **un** paragraphe.
{.foo .bar #baz}

S’affichera de la sorte en html :

<p class="foo bar" id="baz">Voici <strong>un</strong> paragraphe.</p>

Les éléments se positionnent sous les blocs à l’exception des blocs de code et des titres où ils se positionnent à droite :

## Ingrédients { #ingredients }

Pour faire cette recette, s'assure d'avoir:
  - tomates
  - oignon
  - ail
{ .liste-course }

---
{ .mon-joli-trait }

S’affichera:

<h2 id="ingredients">Ingrédients</h2>

<p>Pour faire cette recette, s’assure d’avoir:</p>

<ul class="liste-course">
  <li>tomates</li>
  <li>oignon</li>
  <li>ail</li>
</ul>

<hr class="mon-joli-trait">

Class helper

Sur les blocs

Je peux rajouter les classes:

  • .medium
  • .small

qui proposent deux tailles plus petites à partir d’une certaine largeur d’écran. N’a pas d’influences sur les petits écrans (souvent les blocs trop gros sur grand écran sont à la bonne taille sur petit écran).

Des class sur le body

Dans le front matter, je peux spécifier des classes pour la balise body.

+++
bodyClass = "small-blocks feuille-de-route"
+++

Helpers

À l’heure actuelle, j’ai fait:

  • .small-blocks
  • .medium-blocks

Ça concerne toutes les images et les blocs de code de la page en question.

Dans un thème

Peut permettre de cibler un type de page particulier. Dans ce cas, je pense qu’il faut faire une feuille de syle spécifique qui se mettra dans sass/layout ou sass/themes.

URL management

Default

By default hugo render a page matching the file path within the content directory:

content/studio/rew/index.md → https://example.org/studio/rew/

Override

You can override in the front matter the last segment of the path with slug :

+++
slug = 'room-eq-wizard'
+++

→ https://example.org/studio/room-eq-wizard/

Or the entire path with url :

+++
url = '/mon-joli-studio/room-eq-wizard/'
+++

→ https://example.org/mon-joli-studio/room-eq-wizard/

Title, menu, slug, url

If we only precise title, it will be used in:

  • the title of the page
  • the menu and the slug will be built from the file structure of the content directory.
+++
title = 'Room Eq Wizard'
+++

But we can have more control, we can have:

  • title → the title of the page
  • linkTtitle → the title displayed in the menu
  • slug → our slug (independant from the file structure)
  • weight → the position in the menu, heavier is the weight more it goes down (when no weight is defined it is always heavier)
+++
title = 'Room Eq Wizard'
slug = 'room-eq-wizard'
linkTitle = 'REW'
weight = 10
+++

url change le chemin complet à partir du domain name indépendamment de la structure des dossiers et fichiers.
