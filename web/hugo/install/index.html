Install & Deploy

  • Ne pas oublier le .gitignore
  • Trouver une solution pour importer tous les fichiers de conf nécessaires quand on fait un nouveau site.

sort content

Par défaut par page weight, mais plein de manière de trier les pages: https://gohugo.io/templates/lists/

Créer un nouveau site

hugo new site au-son-du-diois
cp -a ../hugo-config/.gitignore
git init
hugo mod init github.com/matharel/au-son-du-diois

rq: si je fais hugo mod init ... après avoir mis les modules dans hugo.toml, j’obtient une erreur.

Installer le thème comme module Hugo

Cette technique fonctionne très bien et est très facile. Par contre on ne pourra pas faire de modifs au thème dans le cadre du développement du thème.

cp ../hugo-config/hugo.toml .

# hugo.toml

[module]
[[module.imports]]
    path = "github.com/hugo-mods/lazyimg"
[[module.imports]]
    path = "github.com/matharel/seb-doc"

hugo mod get
mkdir accueil interieur exterieur randonnees culturel infos approfondir
touch accueil/index.md interieur/index.md etc ...

La méthode ci-dessus fonctionne très bien. Si je veux mettre à jour le thème:

hugo mod get -u

Installer le thème comme sous-module GIT

Cette méthode permet de faire des modifications au thème qu’on pourra pousser ensuite sur son dépôt. Pratique si on veut continuer à développer le thème.

Hyper important de cloner le sous-module en ssh et pas en http !!!

Sinon, avec github les pulls fonctionnent, mais pas les push. Il n’y a pas de messages d’erreur, juste l’authentification n’est pas possible.

git submodule add git@github.com:matharel/seb-doc.git themes/seb-doc

L’installer en tant que submodule revient à le cloner mais avec intégration au dépôt principal.

Ensuite il suffit de dire à Hugo qu’on utilise le thème:

# nvim hugo.toml
theme = 'seb-doc'

Retirer le submodule git

Si on veut retirer le sous-module (par exemple pour réinstaller le thème en tant que module Hugo):

git rm <path-to-submodule>

En vrai il a aussi fallut que :

  1. je change une entrée dans .git/config
  2. que j’efface .git/modules/themes/seb-doc

Comment développer un thème de manière confortable

  1. j’ai cloner ausondudiois
git clone git@matharel.com:au-son-du-diois.git
mv au-son-du-diois workingtheme
  1. j’ai cloner le theme comme submodule
git submodule add git@github.com:matharel/seb-doc.git themes/seb-doc

si j’ajoute un fichier dans /assets qui override celui dans theme/assets, c’est tout le fichier qui disparait.

Cela implique de bien penser son thème de manière modulaire, car si on a besoin de modifier une ligne du fichier, c’est dommage !

  1. ensuite je push le theme sur git et je mets à jour les modules du thème dans le site concerné.

Deploy on netlify

  1. use git submodule for theme From the documentation: Netlify can’t use a theme installed by the git clone method. Instead, you should install a Hugo theme for your site as a git submodule.

  2. but not in ssh … Je dois retirer le submodule préalablement installé en ssh et le réinstaller en https pour que ça fonctionne

git submodule add https://github.com/matharel/seb-doc themes/seb-doc
  1. Pb avec fichier go.mod

Bon visiblement, il y aurait quand même un souci avec le fichier go.mod ou il faut faire attention avec la version:

invalid go version "1.22.1": must match format 1.23

Premier build: 2m22 Deuxième build: 28s Troisième build en mettant le bazar dans le menu: 26s Ça ne semble pas poser un problème.

netlify vs github page

Github page est limitée à 1giga. Or avec les images, c’est possible qu’on dépasse facilement les 1giga (en tout cas le gîte par exemple).

On ne peut pas faire de github page avec un repo privé (gênant par exemple pour mes notes ou vfub)

Par contre netlify limite à 300 minutes de build par mois. Ça ne semble pas un problème pour moi pour l’instant, mais à surveiller. En vrai, une fois que le cache est en place, ça va vite à s’installer.

templating and variables

Pour utiliser une variable dans du contenu en markdown, il faut obligatoirement passer par un shortcode. Hugo nous met à disposition un embedded shortcode pour récupérer les params du front matter, il suffit de faire:

{{< param param_name >}}

Si veux pouvoir utiliser du markdown dans la variable:

{{% param param_name %}}

Par contre dans un layout, on peut faire référence aux variables du front matter avec:

{{< .Page.Params.param_name >}}

Mettre les modules dans le thèmes pour centraliser les aspects techniques

Il me semble judicieux de charger les modules de lazyimg et lazysize dans les thèmes, car de toutes façon le thème ne fonctionne pas sans eux (il y a des render hook pour les images).

Pour que ça fonctionne, il a fallu que je vendor my modules:

hugo mod vendor
